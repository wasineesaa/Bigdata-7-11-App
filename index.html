วิเคราะห์ระบบแอปพลิเคชัน 7-Eleven

ที่มารูปภาพ: Google Play Store
เป็นระบบ Big Data
1

ประเภทและรูปแบบข้อมูลในระบบ (Data Sources & Types)

Structured Data

1. ข้อมูลสมาชิก (Member Profile)

ชื่อ-นามสกุล, เบอร์โทรศัพท์, วันเดือนปีเกิด และข้อมูลบัญชี All Member

เก็บใน Relational DB เป็นแถวคอลัมน์มาตรฐาน
Structured Data

2. ประวัติธุรกรรม (Transaction History)

รายการสินค้าที่ซื้อ, ราคา, รหัสสาขา, วันและเวลาที่ทำรายการขาย

ข้อมูลบิลขายกว่า 14,000 สาขาทั่วประเทศ
Structured Data

3. ยอดแต้มสะสมและสิทธิประโยชน์

คะแนนคงเหลือ, คูปองส่วนลดที่ได้รับ, ประวัติการใช้สิทธิ์ All Member

ประมวลผลและอัปเดตเรียลไทม์ผ่านตารางฐานข้อมูล
Structured Data

4. ข้อมูลสินค้าและสต็อก (Inventory)

รหัสบาร์โค้ด, รายละเอียดสินค้า, ราคาขาย, และจำนวนสินค้าคงเหลือรายสาขา

เชื่อมโยงกับระบบตัดสต็อกอัตโนมัติ
Semi-structured Data

5. ออเดอร์เดลิเวอรี (7-Delivery Log)

พิกัด GPS จัดส่ง, ที่อยู่, โน้ตถึงพนักงาน, รูปแบบแพ็กเกจ JSON

มีป้ายกำกับยืดหยุ่น เหมาะกับ NoSQL / Lake
Unstructured Data

6. รีวิวและความคิดเห็น (Customer Feedback)

ข้อความรีวิวสินค้าในแอป, รูปภาพสลิปใบเสร็จ หรือรูปภาพสินค้าชำรุด

ข้อมูลดิบไม่มีโครงสร้าง ต้องทำความสะอาดก่อนใช้
2

การประเมินคุณสมบัติ 5V ของ Big Data

1. Volume (ปริมาณ) 5 / 5

จัดเก็บข้อมูลบิลขายจากสาขากว่า 14,000 สาขาทั่วประเทศ รวมหลายพันล้านแถวต่อปี เข้าข่ายระดับ Terabyte+

2. Velocity (ความเร็ว) 5 / 5

การสแกนแต้ม All Member และการสั่งซื้อเดลิเวอรีต้องประมวลผลและอัปเดตสต็อกแบบเรียลไทม์ทันทีในเสี้ยววินาที

3. Variety (ความหลากหลาย) 4 / 5

มีข้อมูลครบถ้วนทั้งตารางฐานข้อมูลเชิงสัมพันธ์, ข้อมูลกึ่งโครงสร้าง (JSON พิกัด) และข้อความรีวิวแบบไม่มีโครงสร้าง

4. Veracity (ความน่าเชื่อถือ) 4 / 5

ข้อมูลธุรกรรมการเงินและแต้มสะสมต้องมีความถูกต้องแม่นยำสูง 100% ป้องกันข้อผิดพลาดและข้อมูลขยะ (Garbage In)

5. Value (มูลค่าของข้อมูล) 5 / 5

นำข้อมูลพฤติกรรมการซื้อมาวิเคราะห์เพื่อทำโปรโมชันเฉพาะบุคคล (Personalized Marketing) และวางแผนสต็อกสินค้าเพิ่มยอดขายได้มหาศาล

3

เส้นทางการไหลของข้อมูล (Data Pipeline: 5 Parts)

Part 1

Data Source

เครื่อง POS หน้าร้าน 7-Eleven, สมาร์ทโฟนของลูกค้า (7-Delivery) และเซ็นเซอร์สต็อก

แหล่งกำเนิดข้อมูล
Part 2

Ingestion

ดึงข้อมูลคำสั่งซื้อเดลิเวอรีทันทีแบบ Streaming และส่งยอดขายรวมรอบดึกแบบ Batch

นำเข้าข้อมูล
Part 3

Storage

เก็บข้อมูลดิบลงใน Data Lake และคัดแยกตารางยอดขายสำคัญเข้าสู่ Data Warehouse

จัดเก็บข้อมูล
Part 4

Analysis

คำนวณแต้มสะสมและตัดสต็อกทันทีแบบ Streaming ควบคู่ Market Basket Analysis แบบ Batch

วิเคราะห์ข้อมูล
Part 5

Consumption

อัปเดตยอดแต้มบนแอปพลิเคชันลูกค้าเรียลไทม์ และสร้าง Dashboard สรุปยอดขายให้ผู้บริหาร

นำไปใช้งาน
4

การค้นพบ Insight และระดับการวิเคราะห์

Business Insight

พฤติกรรมการซื้อร่วมกัน (Market Basket Analysis)

จากการวิเคราะห์ประวัติการซื้อพบว่า "ในช่วงเช้า ลูกค้าที่ซื้อขนมจีบหรือซาลาเปามักจะซื้อกาแฟสด All Café ควบคู่กันเสมอในบิลเดียวกัน"

แนวทางการต่อยอด: จัดทำโปรโมชันเซ็ตคู่ (Combo Set) ลดราคาร่วมกัน หรือยิงคูปองส่วนลดเฉพาะบุคคลผ่านแอปพลิเคชัน All Member ในช่วงเช้า
Analytics Level

Diagnostic & Predictive Analytics

  • • Diagnostic Analytics: วิเคราะห์หาสาเหตุและพฤติกรรมความสัมพันธ์ของสินค้าที่ซื้อร่วมกันในอดีต
  • • Predictive Analytics: ต่อยอดคาดการณ์ความต้องการเพื่อเตรียมสต็อกวัตถุดิบและขนมจีบ/ซาลาเปาให้เพียงพอในแต่ละสาขาล่วงหน้า
อ้างอิงเนื้อหาตามบทเรียน Database Systems and Big Data
